# Explanation Quality Evaluation Kit

This directory contains tools and templates for evaluating the quality of explanations generated by the `/api/risk/explain` endpoint.

---

## Overview

The evaluation kit provides a human-in-the-loop process for assessing explanation quality:

1. **Export** a sample of cases from the investigation queue
2. **Evaluate** each explanation using the standardized rubric
3. **Aggregate** results to identify quality patterns and improvement areas

---

## Quick Start

### Step 1: Export Evaluation Set

```bash
# Export 30 cases (default distribution: CRITICAL=10, HIGH=15, MEDIUM=5)
python tools/export_explain_eval_set.py \
    --base-url http://localhost:8000 \
    --count 30 \
    --out eval/explain_eval_cases.csv

# This creates:
# - eval/explain_eval_cases.csv (case list)
# - eval/raw_explanations/*.json (raw API responses)
```

### Step 2: Optional - Run QA Suggestions

```bash
# Generate rule-based suggestions for potential issues
python tools/qa_suggest_scores.py \
    --raw-dir eval/raw_explanations \
    --out eval/qa_suggestions.csv

# This creates eval/qa_suggestions.csv with potential failure codes
```

### Step 3: Human Evaluation

1. Open `eval/explain_eval_results.csv`
2. For each case in `explain_eval_cases.csv`:
   - Review the raw explanation in `raw_explanations/<user_id>.json`
   - Score each dimension (1-5) using the rubric
   - Mark PASS/FAIL for sensitivity
   - Add failure codes if applicable
   - Add notes

### Step 4: Aggregate Results

1. Copy `eval/explain_eval_summary.md` to a dated file
2. Compute averages and statistics from your results
3. Identify top failure codes and patterns
4. Create action plan for improvements

### Official Benchmark

**Human evaluation is the official benchmark** for explainability quality. The `explain_eval_results.csv` and `explain_eval_summary.md` represent the authoritative evaluation results.

Automated QA experiments (e.g., `qa_suggestions.csv` from `tools/qa_suggest_scores.py`) are **not** used as final evaluation results. They serve only as experimental reference points for potential automated quality checks.

## Evaluation Results (v1.1.0)

### Overview

The v1.1.0 release includes a completed manual evaluation of the `/api/risk/explain` endpoint. Twenty explanation cases were evaluated across five dimensions by human raters.

### Evaluation Dimensions

| Dimension | Purpose |
|-----------|---------|
| **Accuracy & Groundedness** | Are claims grounded in actual risk data? Are scores correct? |
| **Readability** | Is the explanation clear, professional, and logically structured? |
| **Actionability** | Does it provide clear, appropriate next steps for investigators? |
| **Citation Quality** | Are policy citations relevant to the actual risk evidence? |
| **Sensitivity & Privacy** | Does the explanation leak sensitive data? |

### Results Summary

| Dimension | Average Score | Pass Rate |
|-----------|---------------|-----------|
| Accuracy & Groundedness | 4.0 / 5.0 | 100% |
| Readability | 4.0 / 5.0 | 100% |
| Actionability | 3.3 / 5.0 | 100% |
| Citation Quality | 2.1 / 5.0 | 100% |
| Sensitivity & Privacy | — | 100% |

**Overall Quality Distribution:**
- Excellent: 1 case (5%)
- Good: 19 cases (95%)
- Fair: 0 cases (0%)
- Poor: 0 cases (0%)

### Key Findings

**Strengths:**
- The system produces grounded explanations with perfect consistency across all cases
- All claims are supported by actual risk event data
- Privacy protection works correctly — no sensitive data leakage detected
- Schema compliance and response structure validation pass consistently

**Improvement Area:**
- Evidence-to-policy citation alignment is the primary limitation
- 95% of cases contained citation quality issues (irrelevant or excessive citations)
- Citations often reference policies without supporting evidence in the case

### QA Tools

**tools/qa_suggest_scores.py**

A heuristic QA assistance tool that identifies potential quality issues for reviewer attention. It uses rule-based checks to flag:
- Missing or inconsistent fields
- Suspicious score patterns
- Potential citation issues

**Important:** This tool does **not** replace human evaluation. It serves as an assistant to highlight potential issues for manual review. The final evaluation scores in `explain_eval_results.csv` are entirely from human evaluators.

## Evaluation Process Details

### Scoring Dimensions (1-5)

| Dimension | What to Evaluate |
|-----------|------------------|
| **Accuracy** | Are claims grounded in actual data? Are scores correct? |
| **Readability** | Is the explanation clear and well-structured? |
| **Actionability** | Does it provide clear, appropriate next steps? |
| **Citation Quality** | Are citations relevant and accurate? |

### Pass/Fail Check

| Check | Criteria |
|-------|-----------|
| **Sensitivity** | Does the explanation leak sensitive data (IPs, emails, IDs)? |

### Failure Codes

Use failure codes from `explain_failure_taxonomy.md`:

- **A1-A6**: Accuracy issues (hallucination, score mismatch, etc.)
- **B1-B6**: Readability issues (redundancy, jargon, etc.)
- **C1-C6**: Actionability issues (vague action, no action, etc.)
- **D1-D6**: Citation issues (irrelevant, missing, etc.)
- **E1-E5**: Privacy issues (sensitive leakage, ID exposure, etc.)

## Customization Options

### Export Script Options

```bash
python tools/export_explain_eval_set.py --help

Options:
  --base-url URL        API base URL (default: http://localhost:8000)
  --count N             Total cases to export (default: 30)
  --out PATH            Output CSV path (default: eval/explain_eval_cases.csv)
  --raw-dir PATH        Raw explanations directory (default: eval/raw_explanations)
  --audience MODE        Audience mode: investigator or business (default: investigator)
  --no-raw              Skip fetching raw explanations (CSV only)
```

### Case Distribution

The default distribution for 30 cases:
- **CRITICAL**: 10 cases (33%)
- **HIGH**: 15 cases (50%)
- **MEDIUM**: 5 cases (17%)

This focuses evaluation on the most critical cases while maintaining diversity.

## Quality Metrics

### Computing Overall Quality

For each evaluated case:

```
Overall Score = (Accuracy + Readability + Actionability + Citation Quality) / 4
```

**Quality Levels:**
- **Excellent**: Overall ≥ 4.0, Sensitivity PASS
- **Good**: Overall ≥ 3.5, Sensitivity PASS, no dimension < 3
- **Fair**: Overall ≥ 2.5, Sensitivity PASS, at most one dimension < 3
- **Poor**: Overall < 2.5 OR Sensitivity FAIL

### Computing Averages

For each dimension across all evaluated cases:

```
Average = Sum of scores / Number of evaluated cases
```

### Top Failure Codes

Count occurrences of each failure code and rank by frequency.

## Best Practices

### Evaluation Guidelines

1. **Be Consistent:** Use the rubric definitions strictly
2. **Be Specific:** Reference exact text in notes
3. **Consider Context:** Account for risk level when scoring
4. **Calibrate Regularly:** Re-review rubric to ensure shared understanding

### Evaluation Cadence

- **Initial Baseline:** Evaluate 30-50 cases to establish baseline
- **Regression Testing:** Evaluate 10-20 cases after each model/prompt change
- **Quarterly Review:** Full evaluation of 50+ cases to track quality trends

### Team Process

- **Multiple Evaluators:** Have 2-3 people evaluate overlapping cases
- **Calibration Sessions:** Discuss borderline cases to align scoring
- **Track Inter-rater Reliability:** Measure agreement between evaluators

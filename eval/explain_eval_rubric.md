# Explanation Quality Evaluation Rubric

This rubric provides standardized scoring dimensions for evaluating explanations generated by the `/api/risk/explain` endpoint. Human raters use this rubric to assess explanation quality consistently.

---

## Scoring Dimensions

### 1. Accuracy & Groundedness (1-5)

**Definition:** The extent to which the explanation accurately reflects the underlying risk data and avoids ungrounded claims.

| Score | Criteria |
|-------|----------|
| **5 (Excellent)** | All claims are grounded in the risk event data; scores match exactly; findings align with actual factors; no ungrounded assertions |
| **4 (Good)** | Most claims grounded; minor discrepancies (<5% error in score reporting); findings align with risk factors |
| **3 (Fair)** | Generally accurate but notable gaps; some findings not directly supported by data; score reporting errors 5-15% |
| **2 (Poor)** | Significant inaccuracies; multiple ungrounded claims; score reporting errors >15%; findings contradict risk data |
| **1 (Fail)** | Hallucinations or completely ungrounded content; fabricated risk factors; incorrect risk level |

**What to check:**
- Risk score mentioned matches actual `risk_score` value
- Risk level mentioned matches actual `risk_level`
- Detection methods (ML/Rule/Graph) mentioned are actually present
- Key findings align with actual `risk_factors` from the case
- No fabricated factors or false claims about account history

---

### 2. Readability (1-5)

**Definition:** The clarity and comprehensibility of the explanation for a human investigator.

| Score | Criteria |
|-------|----------|
| **5 (Excellent)** | Clear, professional language; logical structure; easy to scan; no jargon overload |
| **4 (Good)** | Generally clear with minor awkward phrasing; structured but could be more concise |
| **3 (Fair)** | Understandable but verbose; some jargon or repetition; moderate effort required to extract key points |
| **2 (Poor)** | Difficult to follow; excessive jargon; confusing sentence structure; requires significant effort |
| **1 (Fail)** | Unreadable; completely unclear; contradictory statements |

**What to check:**
- Summary is concise and coherent
- Key findings are presented clearly (not buried in text)
- Technical terms are used appropriately
- Sentence structure is grammatical
- Overall flow is logical

---

### 3. Actionability (1-5)

**Definition:** The extent to which the explanation enables an investigator to take appropriate next steps.

| Score | Criteria |
|-------|----------|
| **5 (Excellent)** | Clear, specific recommended action; explains why action is needed; investigator knows exactly what to do |
| **4 (Good)** | Clear action provided; minor gaps in reasoning; investigator can proceed with minimal ambiguity |
| **3 (Fair)** | General guidance provided; action may be vague; investigator needs to interpret next steps |
| **2 (Poor)** | Recommended action is generic or unclear; minimal guidance on what to investigate |
| **1 (Fail)** | No recommended action; action is contradictory; or action is inappropriate for risk level |

**What to check:**
- `recommended_action` is present and specific
- Action matches the risk level (e.g., CRITICAL → urgent action)
- Explanation provides enough context for investigator to prioritize
- Action is operationally feasible (not "investigate everything")

---

### 4. Citation Quality (1-5)

**Definition:** The relevance, accuracy, and helpfulness of policy citations (if present).

| Score | Criteria |
|-------|----------|
| **5 (Excellent)** | Citations directly relevant to case; quotes are accurate and contextual; citations help explain reasoning |
| **4 (Good)** | Citations relevant to case; quotes mostly accurate; minor context gaps |
| **3 (Fair)** | Citations somewhat relevant; generic quotes; loose connection to case specifics |
| **2 (Poor)** | Citations tangential or irrelevant; quotes don't connect to findings; citation marks misplaced |
| **1 (Fail)** | No citations when relevant policy exists; or citations completely fabricated/irrelevant |

**What to check:**
- Citation marks `[n]` in findings correspond to actual citations
- Cited policies relate to the risk factors identified
- Quotes from policies are accurate and contextual
- Number of citations is appropriate (not excessive)

---

## Pass/Fail Dimensions

### Response Structure Validity (Pass/Fail)

**Definition:** Whether the explanation response adheres to the expected API contract and structure.

| Result | Criteria |
|--------|----------|
| **PASS** | Response structure matches expected schema; all required fields present; optional fields properly handled |
| **FAIL** | Missing required fields; incorrect field types; structural violations that prevent consumption |

**What to check:**
- All required fields present (`summary`, `key_findings`, `recommended_action`, `citations`, `explanation_source`)
- Field types are correct (arrays are arrays, strings are strings, numbers are numbers)
- **Empty `failure_codes` is valid** — when no errors occurred, `failure_codes: []` is the correct response
- `explanation_source` is one of: `"LLM"` or `"MODEL_FALLBACK"`
- Citations array structure is valid (each has `id`, `doc`, `section`, `quote`, `chunk_id`)

**Failure Code:** `E0 - Structure violation`

---

### Sensitivity & Privacy Leakage (Pass/Fail)

**Definition:** Whether the explanation inappropriately exposes sensitive information.

| Result | Criteria |
|--------|----------|
| **PASS** | No sensitive data leaked; user IDs properly redacted if configured; no raw PII exposed |
| **FAIL** | Sensitive information exposed (IP addresses, emails, phone numbers, full user IDs, account numbers) |

**What to check:**
- No raw IP addresses in explanation text
- No email addresses exposed
- No phone numbers exposed
- No internal database IDs exposed
- User ID is properly redacted if `LOG_REDACT_USER_ID=true`

**Failure Code:** `E1 - Sensitive leakage`

## How to Use This Rubric

### Evaluation Process

1. **Review Case Context:** Start with the `raw_explanations/<user_id>.json` file to understand the full context
2. **Score Each Dimension:** Assign 1-5 scores for each of the 4 scoring dimensions
3. **Check Sensitivity:** Mark PASS/FAIL for privacy leakage
4. **Assign Failure Codes:** If any dimension scores 1-2, assign appropriate codes from `explain_failure_taxonomy.md`
5. **Add Notes:** Document specific issues or positive aspects

### Scoring Guidelines

- **Be Consistent:** Use the same standards across all evaluations
- **Be Specific:** In notes, reference exact text or data points
- **Consider Context:** Account for risk level when assessing actionability
- **Default to Mid-Range:** When unsure, score 3 (Fair) rather than extremes

### Overall Quality Determination

| Overall Quality | Criteria |
|----------------|----------|
| **Excellent** | All dimensions 4-5; sensitivity PASS |
| **Good** | Average score ≥3.5; no dimension below 3; sensitivity PASS |
| **Fair** | Average score ≥2.5; at most one dimension at 1-2; sensitivity PASS |
| **Poor** | Average score <2.5; or multiple dimensions at 1-2; or sensitivity FAIL |
